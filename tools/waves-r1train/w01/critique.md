### 1. ✕ 事例特化・誤爆実測あり（測定前に必ず直すこと）

**#4 数字＋かな1〜2字 → 体言**（`[0-9](?![なねよわぞぜ]|かも)[ぁ-ゖ]{1,2}`）
`[ぁ-ゖ]{1,2}` が貪欲で、助数詞ではなく助動詞・助詞を食う。**旧版で正しかったものを壊している回帰**なのだ。
```
わたしは18です   旧: 18なのだ      → 新: 18ですなのだ    ← 非文
順番は7から      旧: 7から(無変換) → 新: 7からなのだ     ← 助詞ガードを飛び越えた
値段は300でも    旧: 300でも       → 新: 300でもなのだ
```
除外リスト `(?![なねよわぞぜ]|かも)` はコメントに「Sonnet 5なあ」「2かも」と訓練実例名がそのまま書いてある。データからの逆算の証拠なのだ。

**#3 みたい → みたいなのだ**
表層文字列「みたい」しか見ておらず、**マ行五段連用形＋願望「たい」**（飲む/読む/休む/進む/頼む/掴む…＝生産的な大クラス）を巻き込む。これも旧版が正しかった回帰。
```
ゆっくり休みたいです  旧: 休みたいのだ ✓ → 新: 休みたいなのだ ✕
水が飲みたいな        旧: 飲みたいのだ ✓ → 新: 飲みたいなのだ ✕
本が読みたいです      旧: 読みたいのだ ✓ → 新: 読みたいなのだ ✕
```
発火率比は1.01で「一般」に見えるが、**一般に誤る規則**なのだ。

**#2 NAI_STEM の「し」**（ません→未然形復元）
五段サ行（出す/話す/渡す/回す/残す/離す/探す/押す/貸す/示す）の連用形「し」を未然形「し」に写している。正しくは「さ」。表に「さ」の分岐が無いので**生産的クラスで非文を量産する**。
```
荷物を渡しません → 渡しないのだ   （正: 渡さないのだ）
手を離しませんでした → 離しなかったのだ （正: 離さなかったのだ）
資料を回しませんか → 回しないのだ？
```
「ません」規則の発想自体は○だが、表が壊れている。`MASU_STEM` の「し→する」も同じ穴（既存バグ）で、それを ません側に拡大した形なのだ。

**#10 しか → しかないのだ**（train 1件 / held-out 0件）
```
名前はたしか → 名前はたしかないのだ   ← 非文。「たしか」は仮名書き頻出
奈良のしか   → 奈良のしかないのだ     ← 鹿
```
1件のために非文生成リスクを買っている。

**#17b 一段の「…よっ」→「…るのだ」**（train 0件 / held-out 0件 = **誰も救っていない**）
文字クラスに て/で を入れたのが致命的。テ形＋終助詞「よ」＋促音を意向形と誤認する。
```
やめてよっ     → やめてるのだ   （依頼 → 進行相の叙述。意味反転）
ねえ聞いてよっ → 聞いてるのだ
```

**#21 `[らかこせへ]ん` ＋ の**（train 1件 / held-out 0件）
```
ぼくが好きなのはみかんの → みかんのだ？
```
「ん」の直前を未然形の段に限れば名詞を除けるという前提が誤り。「みかん」「ごはん」「せんべい」等、名詞にも同じ段が普通に立つのだ。

**#22 口語否定に「こ」追加**（train 1件 / held-out 0件）
```
おなかがぺこん → ぺこんのだ ／ たぬきがぽこん → ぽこんのだ
```
擬音の「こん」を巻き込む。旧の「ぺこんなのだ」より悪い。

### 2. △ 要注意

**#20 漢字＋え段＋て → るのだ** — **held-out 実データで誤爆を確認**。
```
（実データ）名付けて さくらスクリプト → 名付けるのだ さくらスクリプト  ← 中止法を終止形にして文が壊れた
（実データ）詳しく教えて → 教えるのだ            ← 依頼が叙述に反転
無事に帰れて → 帰れるのだ                       ← 可能形テ形の言いさし → 未来可能
```
文法的には成立するので**採点は通るが意味が変わる**。得点を上げつつ品質は下げる典型なのだ。「め」除外の根拠（初めて/改めて）もデータ由来。

**#8 もんか** — 反語「行くもんか」（強い否定）を疑問「行くもんなのだ？」に変える意味反転。train 1件 / held-out 0件。

**#23 #24 #25 #17c #28 — 無変換ガード群** — 壊すよりマシという判断は正しいが、採点基準上「無変換＝OK」なので**変換品質を上げずに得点だけ上がる**。特に #24（引き伸ばし＋え段/終助詞→raw）は設計上まるごと諦める規則。#28 は日本語の候文・漢字見出しも落とすのを実測（`本日休業日程変更連絡事項確認願上候` → 無変換）。「中国語判定」という説明は不正確なのだ。

**#27 botHeading 分離** — wave内の bot 投稿1件の構造に合わせた分岐で、一般性の説明が弱い。

**#30 SEPARATOR_LINE 数字除外** — 「100 / 15 km」という実例からの逆算。方向は妥当だが動機がデータ由来。

**#7 かね / #16 どう / #13 漢カナ＋な / #14 なん / #9 カタカナ＋か** — 言語的な論拠は堅く、誤爆も作れなかった（`このカレーか→カレーなのだ？`、`オレはバカな→バカなのだ`、`調子はどう→どうなのだ`、`ぶどう/はどう/すいどう` は正しく素通り）。ただし **held-out 発火 0 件**なので、一般性は「論拠として妥当」止まりで**実証されていない**。

### 4. 見送り理由の妥当性

「方言」「倒置」「語彙知識が要る」で見送った判断は正しいのだ。ただし**見送った件（20件）より、当てにいって1件しか救えなかった規則（13本）のほうが有害**という自覚が報告に無い。「一般規則を22本入れた」という自己申告と、「13本が別データで一度も発火しない」という実測が矛盾しているのだ。

### 5. 結論

## no

理由は3つなのだ。

1. **旧版で正しかった出力を壊す回帰が3クラスある** — `18です`（数字）、`休みたいです`（マ行＋たい）、`渡しません`（五段サ行）。いずれも日常的な構文で、**今のコーパスにたまたま出てこないので測定では見えない**。この状態で測ると「99%」がまた出て、3回目の同じ失敗になるのだ。
2. **13本が別データで発火しない** = wave固有の当て込み。これを含めたまま測ると、次のセットで再び72%〜76%に落ちる。
3. **無変換ガードで得点を稼ぐ経路が開いている** — train変化37件中11件が「のだ」を減らしただけ。採点前に「無変換に落として点が上がった件」を別カウントする仕組みが要るのだ。

**測定前の必須修正:** #4（数字：助数詞クラスを限定するか規則ごと撤去）、#3（みたい：直前がマ行連用形の場合を除外、無理なら撤去）、#2（NAI_STEM に五段サ行「さ」を追加、`MASU_STEM` の「し」も同様）、#17b（撤去。訓練でも発火していない）、#10 #21 #22（撤去推奨）。
**測定手順の修正:** score に「変換した件」と「無変換に落とした件」を分けて出す指標を足すこと。
